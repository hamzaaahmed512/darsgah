# Authentication, authorization, payments, and input audit

Repository review: 2026-09-21. The deployed Vercel application and hosted Supabase project may run different code or configuration. Migrations and hosted Auth settings were not applied or verified here.

| Severity | Finding and location | Exploit path | Exact fix / status |
| --- | --- | --- | --- |
| High | Parent portal cookie was a signed, eight-hour bearer token with no server-side revocation (`src/lib/parent-portal.ts`). | A copied cookie remained usable after the parent clicked sign out. | Added a random session ID stored in a service-only, RLS-enabled `parent_portal_sessions` table. Each read checks the record and expiry; logout deletes it. Apply `202609200003_parent_session_revocation.sql` before deploying this code. Old cookies without a session ID now fail validation. |
| High | Permission override action accepted an arbitrary `targetUserId` with the service role (`src/app/(app)/settings/actions.ts`). | A settings manager could write permission rows for an ID without proving it belonged to the current school; they could also grant themselves privileges. | Restricted the action to the principal, verified an active target membership in `user.schoolId`, and denied self-edits before writing. |
| High | Branding upload trusted browser-supplied MIME type and filename extension and accepted SVG (`src/app/(app)/school-profile/actions.ts`). | A settings manager could upload active SVG or mismatched content into a public bucket, then distribute its URL as a school asset. | Removed SVG, checked PNG/JPEG/WebP/ICO signatures server-side, derived extension and content type from bytes, enforced 5 MB, and updated bucket MIME restrictions. Existing SVG files in the bucket require a separate inventory and removal. The bucket is on the Supabase storage origin, separate from the app origin. |
| Medium | School profile action accepted existing logo/favicons URLs from hidden form fields (`src/app/(app)/school-profile/actions.ts`). | A modified request could store an attacker-controlled image URL as school branding. | Existing URLs now come from the authenticated user's server-side school profile. |
| Medium | Free-text search was inserted directly into PostgREST `.or(...)` filter syntax (`src/lib/services/{finance,staff,students}.ts`). | Filter punctuation could change the query expression or cause parsing failures. School filters remained separate `AND` clauses, so cross-school access was not established. | Added `postgrestSearchTerm`, limiting length and excluding filter grammar punctuation. Table operations use the Supabase query builder; no user-supplied raw SQL was found. |
| Release blocker | Password recovery uses hosted Supabase Auth (`src/app/(auth)/forgot-password/actions.ts`, `reset-password/page.tsx`). The local CLI config had a 3600-second email OTP expiry. | A recovery link may remain valid longer than the requested 15 minutes if the hosted project still uses its default. | Local `supabase/config.toml` now sets `otp_expiry = 900`. In hosted project `hgomjumrwdwzkkvsppjs`, set Email OTP Expiration to **900 seconds** and test one-use, expiry, and user binding. Supabase handles randomness and token redemption; app code cannot prove hosted settings. |

Set hosted JWT expiry to 900 seconds and use a session-ID revocation check for immediate invalidation on every sensitive request if that strict requirement remains. Supabase `auth.sessions` and JWT `session_id` can support this, but it is not implemented across PostgREST/RLS. |

## Paths checked

- Four application API routes (`/api/notifications`, `/api/announcements`, `/api/announcements/mark-read`, `/api/announcements/mark-all-read`) call `getCurrentUser` before accessing data. Protected app and platform page trees call `requireUser` or `requirePlatformAdmin` in their layouts; their server actions also check permissions. Parent portal pages/actions use the parent session and student/school equality checks. These checks do not replace a live RLS audit.
- Client IDs in student, staff, finance, and platform operations are generally paired with `user.schoolId` or checked through a school-member lookup. The permission-override exception above was fixed. Service-role calls need continued review whenever new handlers are added because they bypass RLS.
- No Stripe, Razorpay, checkout, payment-provider webhook, or paid-feature entitlement endpoint exists in this repository. Finance actions record school fees manually for authorized staff. Fee totals and discounts are calculated by server services using stored fee structures; client-supplied payment amounts are validated against the server-read outstanding balance. A staff-entered payment is not proof of settlement by a processor. If online payment is added, implement signed webhook verification and server-side settlement before granting access.
- SQL migrations use stored procedures and some `EXECUTE format(...)` calls with SQL identifiers quoted using `%I`; no user-controlled raw SQL execution was found. User data in React is rendered through normal JSX escaping; no `dangerouslySetInnerHTML`, `srcDoc`, or `eval` use was found. These are code findings, not a browser penetration test.
- The branding upload is the only runtime upload path found. Signature checks reject common spoofed MIME/extension cases; full image decoding and removal of previously uploaded active content remain release tasks.

## Verification

`npm run typecheck` passed, and `npx vitest run src/lib/auth/rate-limit.test.ts` passed 2 tests. The new database migration and hosted Supabase configuration require deployment and live verification. See `PREDEPLOY_SECURITY_AUDIT.md` for the other release gates.
